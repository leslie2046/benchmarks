# 个人空间、团队与权限

多租户仅在 `AUTH_MODE=app` 下启用。任何通过已配置 GitHub/GitLab 登录的账号都能使用自己的个人空间，但不会自动获得其他个人或团队的数据访问权。

## 数据归属

- 每个账号首次登录自动创建个人空间，只有本人可访问，不支持邀请其他成员。
- 用户可以创建团队或接受指定账号邀请，加入多个团队。团队成员共享该团队的数据，不共享各自的个人数据。
- 模型供应商、加密 API Key、Dify 配置、测试计划、运行历史、AI 报告及默认 LLM 设置都属于当前空间。新团队为空，不复制创建者的个人凭据。
- 初次启用多租户时，原共享工作区的数据和报告默认归本地管理员的个人空间，不自动分配给 GitHub/GitLab 账号。本部署已于 2026-11-01 按授权将这批业务数据整体迁移到 `software` 团队，管理员个人空间清空；模型配置、测试计划、历史运行、AI 报告及报告文件均由该团队按现有成员权限访问。其他空间和成员角色不变。
- 登录来源不同的账号独立，即使用户名相同也不会自动关联。GitHub 使用不可变数字 ID，OIDC 使用 issuer + subject 识别账号；用户名更改不会改变已有空间和成员关系。

每次密码或 SSO 登录成功后，先显示“选择空间”，由用户选择个人空间或已加入的团队，不自动进入上次使用的空间。空间选择页提供独立“创建团队”入口，不要求已经拥有团队；创建后进入该团队。没有团队时也可进入个人空间，在账户页的设置侧栏中查看收到的邀请。选择前不加载空间业务数据；同一次登录刷新页面保留当前选择，新登录或失去原空间权限后重新选择。

左下角入口在个人空间显示当前用户昵称，在团队空间显示当前团队名称；弹出的账户资料仍显示用户身份。账户菜单始终提供“切换空间”，可返回选择页，其下方提供“创建团队”，个人空间与团队内各角色均可创建自己的团队。只有当前团队空间的 Owner 显示“团队管理”；个人空间不显示，团队管理员和普通成员也不显示。团队内既有成员权限和配置权限仍按三级角色检查。切换空间会重新加载当前应用状态，避免混入上一个空间的数据。选择只保存在当前浏览器标签页，并绑定当前登录会话，不会影响其他标签页的空间选择。

## 团队三级权限

| 操作 | Owner | 管理员 | 普通成员 |
| --- | --- | --- | --- |
| 查看团队数据，使用模型，创建/编辑/运行测试，生成 AI 报告 | 是 | 是 | 是 |
| 查看模型供应商、Dify 配置与空间设置（密钥脱敏） | 是 | 是 | 是 |
| 管理供应商、密钥、Dify、空间默认 LLM，删除测试记录与计划 | 是 | 是 | 否 |
| 修改团队名称，邀请普通成员，撤销邀请 | 是 | 是 | 否 |
| 移除普通成员 | 是 | 是 | 否 |
| 提升/降级管理员、移除管理员 | 是 | 否 | 否 |
| 删除团队 | 是 | 否 | 否 |
| 转让所有权 | 否 | 否 | 否 |
| 退出团队 | 否 | 是 | 是 |

团队始终只有一名 Owner，不支持所有权转让；旧转让接口已移除，也不能通过成员角色接口指定 Owner 或降级现有 Owner。Owner 不能退出自己拥有的团队，可以按原确认流程删除团队。个人空间本人具有完整管理权限。平台管理员只负责部署层的数据库、站点、身份提供方等配置，不默认获得团队成员身份，也没有跨团队浏览数据的应用接口。

普通成员可以用团队保存的凭据调用模型，并从导航查看模型供应商、Dify 配置和空间设置。供应商支持只读查看模型名称、类型、端点和脱敏凭据；默认 LLM 只读展示。普通成员没有新增、编辑、删除、发现/校验模型或保存空间配置的入口，后端也会拒绝这些操作。密钥在服务端用于调用，不向成员返回原文或前缀。界面限制之外，后端对每次请求重新检查成员身份和权限。

团队只能使用保存在该团队的模型。个人空间的模型不会自动共享或复制到团队；如果团队模型列表为空，应由 Owner 或管理员切换到该团队后配置对应类型的模型。

## 指定用户邀请

1. 对方先通过 GitHub 或 GitLab 登录一次 PrismLab；可在左下角账号菜单的“账户”页确认登录来源和准确用户名。
2. 团队 Owner 或管理员进入“成员管理 → 添加成员”，选择 GitHub 或 GitLab / OIDC，填写对方的准确登录用户名，而不是显示昵称、邮箱、数字 ID 或主页链接。
3. 对方进入设置侧栏中的“收到的邀请”，确认接受后才成为普通成员；也可拒绝。团队管理下拉不再提供邀请收件箱入口。不会仅凭邀请自动授予数据权限。
4. 邀请七天有效，发送者可以撤销。接受只限被邀请的账号，不能转发给别人。所有邀请最初仅授予普通成员权限，提升管理员由 Owner 另行操作。

不支持公开邀请链接，不发送邮件通知。在设置侧栏的“收到的邀请”页查看与刷新邀请。一个尚未接受的有效邀请不能重复发送；过期、拒绝或撤销后可以重新邀请。

## 管理界面

当前团队 Owner 的账户菜单显示“团队管理”，不占用侧栏顶部。子菜单仅提供当前团队的成员管理，不提供创建团队、“我的空间”及个人/团队空间列表、“收到的邀请”或“空间设置”快捷项。创建团队位于账户菜单的“切换空间”下方，不依赖团队管理权限；成功后进入新团队的成员管理页。所有空间的账户菜单均可通过独立的“切换空间”入口重新选择个人或团队空间。个人空间没有团队管理入口。

成员管理是独立设置页面：团队概要显示名称、当前角色和成员数；所有者/管理员可从“添加成员”弹窗发送指定账号邀请。成员列表支持搜索和分页，行尾菜单按权限提供角色调整与移除，不提供所有权转让。待接受的邀请单独展示在“待处理邀请”列表，可撤销；个人空间不提供邀请入口。没有复用 Dify 的其他角色，也没有公开邀请链接。

账户/成员/邀请页面使用独立设置侧栏，仅包含收到的邀请及账户，不提供“成员”、“空间设置”和“偏好设置”快捷项。空间设置是工作台配置页面，保留正常工作台导航，不切换到账户设置侧栏，也不显示团队操作卡片。团队成员管理仍可从团队管理菜单中的“成员管理”进入，顶部语言与主题控件保留。账户页显示登录来源、准确用户名和账号 ID，方便他人邀请；昵称不用于匹配邀请。语言和外观仅保存在当前浏览器中。

团队空间中，账户菜单的“创建团队”下方显示当前团队的退出/删除操作：Owner 只能“删除团队”，管理员和普通成员只能“退出团队”；个人空间不显示这些操作。操作先展示包含团队名称与后果说明的确认弹窗，取消不发送请求，执行期间禁止重复操作；失败可重试，操作已成功但刷新失败时仅重试刷新。成功后重新选择可访问空间。后端保持原有角色校验与活动任务删除保护。

账户页的“昵称”可编辑，最长 80 个字符，不接受空白或控制字符。昵称和自选头像属于登录账号，不属于空间；修改后侧栏、账号菜单和团队成员列表同步使用，切换空间或 GitHub/GitLab 重新登录不会覆盖。用户名及身份提供方的不可变账号标识不受影响，邀请仍使用登录来源和准确用户名。

头像支持上传 PNG、JPEG、WebP（不超过 1 MB、400 万像素、单边不超过 4096 px）及移除。服务端验证实际图片内容，重新编码为 256×256 PNG 并移除元数据，保存在 PostgreSQL 身份表，不接受远程图片 URL 或 SVG。本人及同一未删除团队的成员可以读取头像；未登录、非同团队账号或移除成员后不能通过头像地址越权读取。没有设置或加载失败时显示昵称首字符。

左下角账号入口弹出个人菜单，提供账户、切换空间、创建团队、按权限显示的团队管理和退出登录；移除菜单中的偏好设置与外观快捷项。个人设置下不提供“偏好设置”页面；旧 `#preferences` 地址自动转到账户页，语言和主题仍可在顶部工具栏调整。昵称或团队名过长时截断，悬停可查看完整名称，完整登录身份在菜单及账户页查看。手机端通过侧栏抽屉访问相同入口。

## 后端隔离与接口

- 每个新空间对应一个独立 PostgreSQL schema；所有查询在固定的单个 schema 中执行，不将 `public` 作为搜索路径后备。数据库实例和连接账号仍共享，不是每租户单独部署 PostgreSQL。
- `public`（或部署指定的初始 schema）保存身份、空间和成员注册表，以及历史管理员工作区。普通空间的业务表不包含注册表。
- 前端每次业务请求发送 `X-Workspace-Id`，服务端查询真实成员关系后绑定空间；不信任客户端提交的角色。未提供该头时只使用本人个人空间。
- SSE 使用 `workspace_id` 查询参数绑定空间，并在输出后续事件前检查会话和成员是否仍有效。猜测其他空间的记录 ID 无法读取、修改、取消或订阅其运行。
- 定时计划跨空间调度，但每个运行器、任务/进程注册表和报告目录均绑定自己的空间。后台 AI 报告完成时也持有原空间的固定存储实例，不随前端切换空间而改变。
- app 模式下不使用宿主机模型 API Key 环境变量作为租户凭据后备，基准子进程仅继承必要运行环境和该空间明确选择的模型凭据。LLM 能力发现缓存也按空间划分。
- 新空间报告位于 `BENCHMARK_DATA_DIR/workspaces/<space-id>/reports/`；历史管理员报告位置保持不变。

管理 API 位于 `/api/workspaces`：创建/列出团队、成员管理、`invitations` 收件箱、指定账号邀请、接受/拒绝/撤销和 `leave` 退出。没有 `transfer` 转让接口。写操作仍要求真实登录会话、可信 Origin 和 `X-CSRF-Token`。`PATCH` 成员角色只允许 `admin` 或 `member`，不能改变现有 Owner。

删除团队会立即停止所有成员的后续访问并从调度列表移除，但底层 schema 和文件暂时保留，便于事故恢复；不在界面提供撤销功能。有正在运行的测试或 AI 报告时，必须等待完成或取消测试后再删除。物理清理由部署管理员另行安排，不能把“删除团队”当作数据库备份清除。

## 升级与运维

升级前备份完整 PostgreSQL 数据库和 `BENCHMARK_DATA_DIR`，包括加密密钥、报告及会话签名密钥。首次升级重新登录；后端启动时幂等创建空间注册表，不删除或复制原有数据。每个空间自己的业务表结构与原版本一致。

重建 API 与 Web 镜像，保留生产 Compose override（尤其公网 8441 端口），不要只用基础 Compose 覆盖已有部署。升级后依次验证管理员历史数据、第三方账号空个人空间、创建团队、邀请/接受、切换、普通成员配置拦截及移除后的拒绝访问。

完整 `pg_dump` 会包含所有 schema；不要只备份 `public`。同一个应用数据库账号和加密密钥能够访问所有空间，数据库/服务器管理员仍具有运维访问能力；这不是针对数据库管理员的物理安全隔离。不提供按租户独立数据库或加密密钥、团队 SSO、计费或资源配额。
